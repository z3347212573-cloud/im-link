# 在另一台电脑试用

当前版本为 0.1.0 开发版。Windows 已有文件夹运行包；macOS 代码路径已实现，但尚未完成真实主机验收。

## Windows：直接下载运行包

1. 使用你的 GitHub 账号登录，打开本项目的 Releases。
2. 下载 IM-Link-0.1.0-win32-x64.zip，完整解压到一个固定文件夹。
3. 双击文件夹内的 IM Link.exe。不能只复制 exe，旁边的 resources 和运行库也要保留。
4. 工具会扫描这台电脑自己的 Agent 配置。按需要选择导入，或者根据指引添加一个测试用飞书机器人。
5. 选择本机的 DSH 或 Claude Code 设置，保存后按提示重开对应 Agent，再验证飞书私聊。

当前包不包含 DSH 的安装和账号配置。目标 Agent 需要在那台电脑上已经可以正常使用。

## macOS：先从源码运行

安装 Git、Node.js 22 或更新版本，并准备好本机 Agent。克隆仓库后，在仓库文件夹中执行：

    npm ci
    npm start

需要检查代码和测试时：

    npm run check
    npm test

原生启动钩子探针目前针对 Windows，不要直接在 macOS 执行带 --hooks 的探针。macOS 的钥匙串、插件生命周期和各 Agent 入口仍需在实际主机验证。

如果需要本机文件夹构建，在 macOS 上执行：

    npm run package

该构建未签名或公证，不属于已经完成验收的 macOS 发布包。

## 配置与凭据

仓库和运行包只包含程序与文档，不包含当前电脑的机器人密钥、会话或本机数据。

另一台电脑使用自己的 .im-link 数据目录；Windows 凭据受当前用户 DPAPI 保护，macOS 使用本机钥匙串，不能直接把加密数据文件复制过去就当作配置同步。可以在新电脑导入那台机器已有的接入，或重新填写测试机器人的信息。

本版本只协调同一台电脑上的接入所有权。跨电脑测试建议使用独立测试机器人，或者先停用原电脑对应接入，再在新电脑启用同一个机器人。

## 当前验收边界

已完成 Windows 桌面交互和隔离测试。真实飞书收发、DSH 实际 profile 加载、IDE／桌面入口和 macOS 的结果应分别记录，不能用一台机器上测试通过代替其他入口。

如果启动或接入失败，请保留报错、操作步骤、系统和 Agent 版本；不要分享密钥或完整凭据文件。
