## 3. 接入方式的更新

前期调查发现，Claude 官方 channels 需要按会话选择启用，普通渠道插件默认把事件推入当前会话。

当前实现改为：

1. 用户级原生生命周期钩子随普通 Agent 会话启动。
2. 钩子启动 Agent 侧组件，并登记所属 Claude 进程。
3. 组件直接接收飞书事件，用 SDK 管理 IM 专属会话。
4. SDK 子会话带递归保护标记，不重复启动渠道组件。
5. 所属会话全部结束或所属进程不再存活时，关闭组件。

这不依赖管理窗口或专用快捷方式，也不修改官方程序代码。它仍然是需要按版本和入口验证的适配实现。

官方依据：

- [Claude hooks：生命周期与适用入口](https://code.claude.com/docs/en/hooks)
- [Claude SDK 会话](https://code.claude.com/docs/en/agent-sdk/sessions)
- [Claude channels](https://code.claude.com/docs/en/channels)

## 5. 首次试用

1. 打开 Windows 开发版。工具只扫描和展示，不会自行导入。
2. 在“发现的已有接入”中选择想管理的机器人，或者跟随添加指引创建测试机器人。
3. 选择目标 Agent 设置和默认工作文件夹，保存配置。
4. 按提示手动重开目标 Agent，管理窗口可以关闭。
5. 在飞书私聊发送一条普通请求，确认回复；再验证 /new、正常重开恢复、提问与确认。
6. 回到管理工具更换绑定，检查旧任务等待、新会话和失败恢复。

保存配置、凭据校验和双向通信是不同的状态；只有实际完成请求与 Agent 回复才记录通信验证成功。
