# 技术验证方案

编写日期：2026-10-29。需求依据：《首版需求说明》。

状态：验证计划，尚未执行产品级实验。本方案引用的是前期只读资料核查，不能作为端到端能力已经打通的证明。

## 1. 验证目的

在开发完整界面和跨平台安装包之前，先确认已约定的使用体验能否实现：原有入口启动、管理工具退出、渠道独立会话、/new、IM 内交互、任务结束后切换。

验证不以新快捷方式替代原入口，不以向任意当前终端推送消息替代专属会话，也不以另起一个常驻统一消息平台替代 Agent 侧适配。

## 2. 前期证据与局限

资料核查时间：2026-10-28。下表区分用户提供的信息、文档证据和未验证推论；执行实验前需核对实际安装版本与当时官方文档。

| 对象 | 已有证据 | 不能据此承诺的能力 |
| --- | --- | --- |
| DSH 飞书接入 | 用户说明：Cordis 插件树、profile 补丁层注册、官方飞书 SDK、独立凭证文件，重启后由主进程建立出站长连接 | 本次未复核插件源码，也未验证当前运行状态或跨平台安装流程 |
| DSH 本机识别 | 前期只读识别到 npm 包 @deepseek-ai/dsh，版本 0.2.1-alpha.2 | 不代表该版本有本项目需要的完整会话与交互接口 |
| 飞书 | 官方支持应用机器人收发消息、自建应用长连接接收事件 | 凭据有效不代表事件权限、订阅和双向消息已接通；自定义 webhook 通知机器人不能代替收消息入口 |
| Claude Code channels | 官方已有将事件推入运行中会话的入口，列出 Telegram、Discord、iMessage 插件 | 不代表飞书开箱即用，也不代表自动创建 IM 专属会话 |
| Claude Code 启用方式 | 文档要求按会话启用 channels；保存插件、MCP、凭据和组织允许策略不能替代启用 | 尚未确认存在一个官方用户级设置，可以使所有原入口自动启用渠道 |
| Claude Code 原入口 | CLI、VS Code、桌面使用不同启动路径；VS Code 有进程包装配置 | shell alias 或包装命令不能自动覆盖所有入口；包装参数在图形扩展中的实际作用尚未实测 |
| Claude 会话接口 | 官方 CLI／SDK 有新建、返回 session ID、按具体 ID 恢复等机制 | 普通 channels 通知并无选择其他会话的通用接口；不能认定 IM 文本 /new 自动等于终端命令 |

前期只读检查没有修改用户配置、没有启动推理，也没有用真实飞书消息做端到端验证。

## 3. 候选结构

### 3.1 按需运行的配置管理器

负责发现配置、管理绑定、凭据存储、安装适配组件、写入注册项、展示差异、备份和回滚，以及提供诊断入口。

管理器不承载日常消息流，不负责在退出后维持统一消息服务。

### 3.2 Agent 侧适配

逻辑上区分三个职责，是否拆包由实验决定：

| 职责 | 内容 |
| --- | --- |
| 渠道接入 | 飞书 SDK、事件解析、文字发送、重复事件识别 |
| Agent 适配 | DSH 扩展注册，或 Claude Code 经验证的会话与交互接口 |
| 私聊会话管理 | 私聊映射、请求顺序、/new、任务交互、会话恢复、渠道接收所有权 |

DSH 优先复核和复用用户现有的插件路径。Claude Code 需要比较官方渠道插件方式和 Agent 侧专用会话组件：前者默认绑定当前会话，后者如何从原有入口启动仍需验证。二者均不能直接标记为已满足全部要求。

如果实验发现某种方案只能靠独立常驻平台、专用启动入口或修改官方代码完成，就记录为不符合当前范围，不直接采用。

### 3.3 需要持久保存的信息

候选数据字段包括：渠道实例 ID、Agent 类型、Agent 设置 ID、凭据引用、绑定版本、默认工作文件夹、私聊 ID、Agent 会话 ID、待处理控制操作和最近验证结果。

会话映射至少由“渠道实例 + 私聊 + 当前绑定版本”区分。绑定版本用于保证切换之后，包括切回曾用过的 Agent 时，也不会误恢复旧绑定的上下文。

所有权与锁的具体实现待验证。它只负责同一渠道接收方的协调，不能据此增加一个必须常驻的管理平台服务。

## 4. 验证顺序

先查源码和官方接口，再做可控的本机实验，最后开展实际渠道验证和双平台验证。实验产物与日常配置分离，保存变更差异和回滚点。

验证前确认有合法可用的测试接入信息，不在输出中打印凭据。文档阶段不索取用户密钥。

### V0：获取最小可复现基线

步骤：

1. 记录操作系统、安装方式、Agent 和 SDK 版本、正在使用的原有入口。
2. 定位 DSH 实际飞书插件源码、Cordis 注册项和会话接口；用户提供的接入描述仍保留为独立证据来源。
3. 记录 Claude Code 的渠道加载、会话管理和提问／确认接口及其适用模式。
4. 确认适配组件生命周期和配置落点，不读取或输出凭据值、私聊日志。

通过条件：能写出每个接入点的实际文件或官方接口依据；找不到的部分列为未确认，不用名称相似的通用 MCP 功能代替。

### V1：原有入口自动加载

分别在 Windows、macOS 上按适用入口验证：

| 入口 | 必须检查的情况 |
| --- | --- |
| 普通终端中的原 Agent 命令 | 已有终端、新终端、不同工作文件夹、不同已配置设置 |
| IDE 集成终端 | 是否沿用同一命令路径，是否受 shell 配置影响 |
| IDE 图形扩展 | 是否启动自己的捆绑程序，是否支持受控包装，是否加载相同用户配置 |
| 原有桌面入口 | 是否提供扩展生命周期入口，是否支持渠道启用；不适用项要说明原因 |

操作过程：配置一次 → 完全退出管理工具及其子服务 → 使用原有入口启动 Agent → 观察适配组件启动 → 实测 IM 请求与回复 → 退出 Agent → 检查组件结束和接收所有权释放。

必须记录新旧终端环境、是否需要重启主进程，以及是否对用户现有启动配置产生影响。

通过条件：每个适用入口有真实验证记录，用户不用改用新命令或专用快捷方式。某一入口不通过则该入口保持未通过，不由其他入口的成功代替。

阻塞处理：若 Claude Code 缺乏足以覆盖约定入口的扩展点，给出官方依据、实验结果及受影响入口，再讨论如何解决；不能直接宣称修改用户设置即可实现。

### V2：飞书文字收发与管理器退出

使用同一个测试用飞书应用机器人，依次连接 DSH 和 Claude Code。

检查应用权限、订阅、长连接事件、文字发送和回复关联。凭据校验、连接建立、收到私聊事件、Agent 处理完成、回复回原私聊分别记录。

在管理器完全退出期间重复请求，确认日常通信由 Agent 侧组件处理。重新打开管理器后，应能展示实际或最近验证结果。

通过条件：Agent 运行时完成双向文字通信；群事件不创建任务；无工具层账号限定或强制配对；不输出凭据。

### V3：专属会话、隔离与恢复

实验：

1. 在普通终端会话写入一个唯一标记，在 IM 专属会话写入另一个标记，检查上下文互不混用。
2. 使用两个测试私聊写入不同标记，确认对应不同 Agent 会话。
3. 正常退出、重新启动 Agent，恢复各私聊精确的原会话。
4. 在其他终端产生一个更新的会话，确认 IM 没有因“最近会话”规则而恢复错误目标。
5. 新开多个 Agent 进程，检查同一个渠道实例只产生一个活跃接收方。

通过条件：映射可持久保存并按 ID 恢复，无上下文串用、重复回复或多个进程抢收。

### V4：/new 顺序

验证空闲 /new，以及“任务 A → /new → 消息 B”。

忙碌时先确认收到新建请求，继续 A；A 的结果回复完成后创建空白会话，发出“已新建会话”，再执行 B。检查新会话无旧标记，而原会话记录仍存在。

额外检查重复事件、连续 /new 和进程重启边界，避免同一事件造成重复新建。具体去重和持久化机制属于实现选择，不改变已确认的顺序。

通过条件：用户可观察的执行顺序与需求一致，没有中断 A，没有让 B 落入旧会话，也没有提前谎报新建成功。

### V5：IM 提问与操作确认

分别触发一个普通问题、一个选项选择和一个沿用 Agent 原有权限规则的确认。

检查问题是否出现在原私聊，用户回答是否送到正确的请求，以及等待期间 /new、切换请求是否保持等待。使用另一个私聊的回答测试请求关联，不得误确认。

检查所选运行模式是否会忽略某类交互或权限回调；官方渠道插件方式与专用会话方式必须分别核实，不能混用两种模式的功能承诺。

通过条件：任务可在 IM 内继续完成，不依赖用户回终端点选，不靠统一跳过权限来完成实验。

### V6：切换与回滚

步骤：

1. 机器人先绑定 DSH，保存原配置快照并完成一次消息通信。
2. 启动任务 A，提交切换到 Claude Code，发送消息 B。
3. 等待当前已开始的任务完成，再停用原接入、应用目标接入。
4. 如需用户重启 Agent，显示等待状态；在旧接入仍活跃时不标记切换完成。
5. 目标接通后以空白会话处理 B；再切回 DSH，检查不会恢复上次绑定的旧上下文。
6. 分别注入安装失败、写配置失败和目标接入失败，验证原配置与绑定恢复。

多私聊同时有任务时，检查对整个渠道实例的切换等待行为。群聊不在本实验范围内。

通过条件：无双接收，任务无中断，新消息去向明确，失败恢复有证据。配置恢复与通信恢复分开报告。

### V7：配置、凭据和生命周期

验证自动发现与选择导入、多套设置选择、无关字段保留、默认工作文件夹、解绑和删除。

候选凭据方案可使用操作系统凭据存储或受其保护的本机加密存储；Windows、macOS 的实际实现分别验证。记录工具储存和插件读取两端的方式，不因工具库加密就忽略 Agent 侧落点。

检查切换无需再次输入凭据，管理器退出不影响读取。清理时保留其他渠道仍引用的配置、凭据和共享依赖，不删除用户 Agent 的历史会话。

通过条件：符合需求的本机加密与复用目标；清理有明确归属，不扩展为删除远端机器人或其他用户配置。

## 5. 验证记录模板

| 字段 | 内容 |
| --- | --- |
| 验证编号 | V0—V7 及具体用例 |
| 系统与版本 | OS、Agent、插件、SDK、安装方式 |
| 入口 | 原有启动命令或入口类别；日志中不包含敏感参数 |
| 配置变更 | 修改了哪些受管理条目，备份与恢复位置 |
| 前置状态 | 管理器是否已退出，Agent 是否运行，当前绑定 |
| 观察证据 | 进程生命周期、事件编号、会话 ID、消息顺序等最小必要证据 |
| 结果 | 通过／未通过／未验证／不适用，不适用需说明 |
| 限制 | 账户、组织策略、入口、平台或版本条件 |
| 回滚结果 | 配置是否恢复、通信是否恢复、是否需用户重启 |

禁止把计划、文档推断或仅 CLI 帮助输出标记为实验通过。涉及账户权益和授权方式时，应依据实际采用的接口单独核实，不承诺通用复用订阅。

## 6. 进入完整开发的条件

建议先完成 V0、V1、V3、V5 中会决定整体结构的验证，再实现完整界面。

只有实际证明原入口自动加载、管理工具退出、专属会话和远程交互能够组合工作，才能冻结 Agent 侧适配方案。随后完成 V2、V4、V6、V7 和双平台回归。

Windows 的成功不能代替 macOS 验证。没有可用 macOS 环境时，明确记录未验证，不宣称首版跨平台能力已经完成。

如果关键目标验证失败，交付具体受阻能力和替代方案的差异，不以常驻网关、新快捷方式或共享当前终端会话悄悄替代已确认要求。
