# 首版需求说明

确认日期：2026-10-29。

状态：需求范围已经用户确认；已开始实现 0.1.0 开发版。本文是需求基线，实际完成与验收状态见《验证结果与未完成项》。

## 1. 问题与目标

用户使用多个 Agent。每次切换 Agent，需要重复接入 IM 渠道；现有接入关系和参数分散，缺少统一的可视化管理入口。

本项目提供一个类似 CC Switch 的本机配置管理工具，负责识别 Agent、管理渠道接入信息、安装渠道扩展、配置绑定和切换。日常消息由 Agent 及其适配组件直接处理，管理工具完成配置后可以完全退出。

先解决用户自身的真实使用问题，并按可开源项目组织。

## 2. 首版范围

| 维度 | 已确认范围 |
| --- | --- |
| 操作系统 | Windows、macOS，分别管理本机 |
| IM | 飞书，单对单私聊 |
| Agent | DSH、Claude Code |
| 消息 | 文字请求、任务回复、Agent 提问与确认、/new |
| 账号 | 工具不增加使用账号限定，不要求强制配对 |
| 数据 | 本机保存，不做跨设备同步 |
| 渠道管理 | 添加、查看、导入、修改、绑定、切换、解绑、删除 |
| Agent 设置 | 同一种 Agent 可管理多套独立设置 |

后续扩展方向包括 QQ、微信、Telegram、Codex、群聊、图片和文件消息；这些不属于首版验收范围。此前讨论过的群聊独立会话和 @ 触发规则不在首版实现。

首版不管理模型提供商、模型 API 地址、通用 MCP 或 Skills 配置，不做跨 Agent 的任务历史交接，也不引入承接所有日常消息的常驻管理平台服务。

## 3. 运行边界

### 3.1 管理工具

管理工具负责扫描、导入、安装、配置、验证、切换和恢复。完成操作后允许完全退出，不要求托盘保活、隐藏服务或常驻网页后端。

### 3.2 Agent 侧适配组件

适配组件可以由本项目开发，也可以复用经过验证的插件。其职责包括渠道连接、消息收发、独立会话映射、/new、请求排队，以及把 Agent 提问和确认返回 IM。

适配组件随 Agent 的生命周期工作。它可以是进程内插件或 Agent 管理的子进程，具体方式逐个 Agent 验证。不能以“没有原生 IM 功能”直接判定不支持，也不能假定所有 Agent 都有相同的扩展接口。

通过受支持的扩展注册入口、用户配置及必要的启动适配接入，不修改 Agent 官方程序代码。

### 3.3 原有启动方式

完成配置后，用户继续通过原有终端命令、IDE 等入口打开 Agent，已绑定渠道应自动加载。管理工具和专用快捷方式均不是日常启动的必要入口。

原有启动入口需要逐项验证并公开覆盖范围。不能把“某个包装命令可用”标记成“任意原有入口均可用”。尚未覆盖的入口必须保留为未通过项，不得悄悄降低需求。

Agent 或其必要组件没有运行时，本工具不提供独立离线执行能力。离线期间消息能否由渠道补投，以及 Agent 重启后的任务恢复边界，属于技术验证项，不能承诺自动补跑。

## 4. 核心对象与关系

| 对象 | 含义 |
| --- | --- |
| 渠道实例 | 一个具体的飞书机器人接入，含名称、平台标识、凭据引用和接入设置 |
| Agent 类型 | DSH 或 Claude Code |
| Agent 设置 | 某个 Agent 的一套独立配置目标，包含配置位置、扩展接入方式等 |
| 绑定 | 一个渠道实例与一套 Agent 设置之间的接入关系，可指定默认工作文件夹 |
| IM 会话映射 | 某个渠道实例中的某个私聊，与专属 Agent 会话的对应关系 |

约束：

- 一个渠道实例同一时间只绑定一个 Agent 的一套设置。
- 一个 Agent 或一套 Agent 设置可以绑定多个渠道实例。
- 同一种 Agent 支持多套独立设置；仅有一套时直接显示 Agent 名称，有多套时才展示设置名称供选择。
- 每个私聊拥有自己的 Agent 专属会话，不借用用户正在使用的普通终端会话。
- 不同私聊的上下文和 /new 操作相互独立；不限定账号不意味着共享上下文。
- 默认工作文件夹属于绑定；可由用户选择，存在可读的 Agent 默认值时可以预填。

## 5. 添加、导入与配置

### 5.1 添加渠道

首次添加机器人提供分步指引，帮助用户创建机器人、取得参数并配置相关权限和消息接入。已有机器人可以直接填写接入信息。

用户选择 Agent 及具体设置，可以选择默认工作文件夹。工具识别所需扩展和依赖，安装、注册、写入相关配置并验证结果。

指引应区分需要用户在飞书后台完成的步骤与工具可以执行的步骤，不承诺平台未提供的全自动机器人创建能力。

### 5.2 发现现有配置

打开工具时扫描已支持的配置位置，展示发现结果，由用户选择是否导入。识别到配置不等于获准接管或覆盖。

修改前保存备份，只修改本次接入涉及且工具能够识别的条目，保留其他配置。Agent 设置可以指向不同配置位置，不能把所有 profile 都解释成 Agent 原生提供的同名功能。

### 5.3 凭据

渠道接入信息在本机加密保存，界面默认隐藏。绑定切换时复用已保存的信息，不要求重新填写。首版不做跨设备同步。

工具自身保存的凭据与 Agent 插件读取凭据的方式需要分别验证，不能把 Agent 侧额外生成的明文文件描述成已加密。具体凭据传递方案在技术验证中确定。

## 6. 会话和消息规则

### 6.1 普通消息

私聊直接处理文字消息。每个私聊使用对应的专属 Agent 会话。回复回到发起请求的原私聊。

Agent 需要回答问题、选择选项或确认操作时，应将问题和选项发送到原 IM 聊天，用户在那里回复后继续执行。沿用 Agent 已有权限规则，不通过统一关闭权限检查来替代交互适配。

等待用户回复属于任务仍未完成的状态。确认或回答必须关联到正确的私聊、任务和问题，不能应用到其他会话。

### 6.2 /new

- 空闲时收到 /new，为当前私聊创建空白 Agent 会话，更新映射，并回复“已新建会话”。
- 忙碌时收到 /new，保留当前任务运行，先提示将在任务完成后新建。
- 当前任务完成并回复结果后，执行新建；成功后回复“已新建会话”。
- /new 后收到的普通消息，在新会话中处理。
- 新建只影响发出指令的那个私聊，保留渠道绑定、Agent 设置和默认工作文件夹。
- 新建不额外删除旧 Agent 已保存的会话记录，不撤销任务已经产生的文件修改。

已确认的关键顺序：任务 A 执行中 → 收到 /new → 收到消息 B → 完成 A 并回复 → 新建会话并提示成功 → 在新会话处理 B。

### 6.3 重新打开 Agent

渠道绑定没有改变时，Agent 正常关闭、重新打开后应恢复该私聊原有的专属会话。不得用“最近使用的任意会话”代替已记录的精确映射。

正在执行的任务遇到进程异常退出时，不能仅凭恢复会话就认定任务已完成，也不能无条件重发可能重复产生副作用的操作。异常任务如何辨认和提示由验证结果明确。

## 7. 绑定切换

用户在渠道列表选择目标 Agent 和具体设置。

若渠道对应的当前任务尚未完成，等待其完成再切换，不暂停任务。等待期间的新消息排队，切换成功后交给目标 Agent；界面显示等待状态。

同一个渠道实例的切换作用于该渠道的绑定，因此需要检查其各私聊当前正在处理的任务，避免只等待某一私聊就切走整个机器人。

切换成功后，目标 Agent 为收到消息的私聊建立空白会话，不迁移之前聊天内容。旧 Agent 原有记录保持原样。以后再次更换绑定也属于一次新的切换，不能因为目标 Agent 曾经使用过就误恢复上次绑定的上下文。

运行时应确保一个渠道实例没有两个活跃接收方。仅写入新配置、但旧接收方仍有效时，不能显示“已完成切换”。

## 8. 组件重启与失败恢复

由工具安装和管理的渠道组件，可以由工具自动重启。涉及用户正在使用的 Agent 主进程时，提示用户手动重启，不自动关闭或重启主进程。

安装、注册、配置或切换失败时，恢复本次操作修改的配置，保留原绑定，说明失败原因和下一步操作。

恢复配置与恢复通信分别判断；如果需要用户重启原 Agent 才能恢复通信，明确显示该步骤，不能将配置回滚直接标成在线。

## 9. 界面

### 9.1 渠道首页

按渠道展示，可直接更换绑定。每行至少能看出渠道名称、当前 Agent、具体设置、接入状态和可执行操作。绑定详情可以查看或修改默认工作文件夹。

添加渠道提供指引；发现的现有配置提供导入入口；解绑与删除使用不同操作。

### 9.2 Agent 页面

查看本机已识别的 Agent、其独立设置、已绑定渠道以及相关插件安装状态。

### 9.3 状态

| 状态 | 含义 |
| --- | --- |
| 未绑定 | 已保存渠道，尚未绑定 Agent |
| 已保存配置 | 所需配置已写入，尚不能证明当前通信可用 |
| 等待任务结束后切换 | 接受了切换请求，正在等待既有任务完成 |
| 等待重启 | 生效或恢复通信需要用户重启 Agent |
| 已验证接通 | 在明确时间、入口和 Agent 运行状态下，验证了请求与回复 |
| 操作失败／恢复待完成 | 操作失败，显示回滚结果及剩余处理步骤 |

“已验证接通”应保留验证时间和范围；工具再次打开时，应读取当前状态或展示上次验证时间，不能把过去成功当作当前持续在线的证明。

## 10. 解绑和删除

- 解绑：停用当前 Agent 接入，保留渠道信息和凭据，以便以后重新绑定。
- 删除渠道：清理本工具保存的渠道信息和对应接入配置；Agent 原有聊天记录保持原样。
- 飞书后台机器人由用户自行管理，本工具的“删除渠道”不等于删除飞书后台应用。
- 只清理本工具管理且能够确认归属的配置，保留其他渠道仍在使用的共享配置和依赖。

## 11. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 原有入口启动 | Windows、macOS 的约定入口分别通过；管理工具已完全退出，渠道仍随 Agent 加载 |
| AC-02 | 导入 | 展示发现结果，未选择导入的配置不被覆盖；修改保留无关字段且存在可恢复备份 |
| AC-03 | 新建 | 跟随指引添加一个飞书机器人，绑定目标 Agent，完成文字请求与回复 |
| AC-04 | 专属会话 | IM 上下文与普通终端会话互不混用；两个私聊也互不混用 |
| AC-05 | 空闲 /new | 得到空白上下文与成功提示，原记录和绑定设置仍保留 |
| AC-06 | 忙时 /new | 严格执行 A 完成与回复 → 新建并提示 → 在新会话执行 B，无任务中断 |
| AC-07 | 正常重开 | 重开 Agent 后恢复精确的原私聊会话，其他最近使用会话不被误选 |
| AC-08 | 任务交互 | 问题和操作确认发回原私聊，用户回答后对应任务继续，其他会话不受影响 |
| AC-09 | 切换 | 同一个机器人在 DSH、Claude Code 间切换；等待既有任务完成、新会话无旧上下文、没有双接收 |
| AC-10 | 失败恢复 | 安装失败、配置写入失败或目标接入失败时，原配置与原绑定可恢复，必要重启明确提示 |
| AC-11 | 多套设置 | 仅修改选定的设置；单套时界面简洁，多套时可明确选择 |
| AC-12 | 凭据复用 | 本机加密保存、默认隐藏；更换 Agent 不需再次填写渠道信息；日志不输出凭据 |
| AC-13 | 解绑／删除 | 解绑保留可复用信息；删除清理工具管理的接入，保留旧聊天记录和其他渠道配置 |
| AC-14 | 首版边界 | 不处理群聊，不强制账号配对；仅承诺文字、任务回复和 /new |

## 12. 尚待技术验证

以下属于已经确认的目标，但尚无实现验证：

1. Claude Code 在全部约定原有入口中自动加载渠道，尤其终端、IDE、桌面入口之间的差异。
2. Agent 侧组件在管理工具退出后维持专属会话，并支持精确恢复、/new 和远程交互。
3. 接入所有权转移、任务完成等待、失败回滚的运行时一致性。
4. Windows、macOS 上的插件路径、依赖、凭据读取与组件生命周期一致性。

相关验证步骤见《技术验证方案》。技术障碍不能通过修改已确认范围来隐藏；如验证结果要求改变用户体验，应带着具体证据重新讨论。
